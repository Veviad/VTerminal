## Shell tracking through startup tools

VTerminal now preserves its shell integration when startup tools replace the local shell. This fixes saved-host tabs that remained marked disconnected after a successful SSH login, and local Agent commands that were incorrectly blocked as busy. The startup bridge handles ordinary shell exec handoffs without depending on a particular CLI or changing user dotfiles, and keeps the user's startup directory and aliases.

Each tab establishes its own private tracking scope before the shell starts. Remote prompt reports and unrelated integrations cannot claim local shell ownership, even if local startup fails. Private tracking identifiers are kept out of forwarded shell environments.

When tracking cannot be established, the SSH banner reports that connection status is unavailable and offers a new SSH tab. Agent commands explain that shell integration is unavailable and remain unexecuted until an idle prompt can be verified. Tools that explicitly bypass startup aliases, discard the integration environment, or replace the shell with an unsupported interpreter may still require configuration.

Generated integration files now repair themselves when missing or corrupted, including the login-stage startup file. Existing terminal scrollback, saved hosts, and AI transcripts remain available. Open a fresh terminal tab after updating so it loads the repaired integration.
