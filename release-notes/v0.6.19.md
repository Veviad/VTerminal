## Full access and SSH prompts

- Show SSH prompt confirmation separately from command approval. Full access authorizes privileged commands without retaining an outdated privileged-command approval explanation.
- When selecting Full for a waiting command, continue that exact command if the current SSH shell proof is reusable. Otherwise keep the explicit empty-prompt check without treating the mode change as proof of terminal readiness.
- Keep edited or cleared command drafts pending for an explicit Run or Skip, so selecting Full cannot execute the original proposal in place of the visible edit.
- Keep guarded modes' approval explanations specific to the selected permission mode.
- Keep the visible mode aligned with accepted native updates even when a newer queued selection fails. Superseded Full selections cannot automatically release a command.

## Starting a new conversation

- Keep controls and Agent dispatch fenced while the outgoing conversation is archived and the terminal is reset, so a delayed New Chat operation cannot discard a new goal or permission choice.
- Discard late permission acknowledgements while New Chat owns the conversation, including when exit preparation prevents archiving, so they cannot release an outgoing command.
- New and reopened conversations continue to start visibly at Confirm.

Saved deny rules, disabled capabilities, private-output handling, and scheduled authorization limits remain enforced. No database migration is required.
