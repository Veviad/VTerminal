## Commands and prompts on a schedule

VTerminal now runs a saved sequence of shell commands and AI prompts on a schedule, against a local shell or a saved SSH host. Scheduled Actions is experimental and switched off by default in **Settings → Schedules**.

- An action authorizes nothing until you arm a permission mode on it, and editing its steps, its target or its attachments resets that arming. **Full** is never offered to a schedule.
- Anything the armed mode does not cover is skipped and recorded the moment it is proposed, rather than waiting on an approval nobody is there to give.
- Runs happen in the background by default. Driving a real terminal tab is a separate switch, because the timers that drive a tab are throttled while the window is minimised — which is usually when a schedule fires.
- Every run keeps a per-step record: what ran, its exit code, a capped extract of its output, and what the action wanted to do and was not allowed to.
- Actions fire only while VTerminal is open. There is no tray icon, no launch agent and no background process. An occurrence missed while the app was closed is skipped, or caught up at most once after the app has settled.
- A run that hits the model's step limit pauses and stays paused. Nothing continues it on its own.
- MCP tools need a grant you already made through the ordinary approval card; a schedule never opens that gate itself. Web access is per action and off by default, and the global setting can only narrow it.

## Long conversations get summarized, not silently forgotten

A conversation that outgrew the model's context window used to lose its oldest turns without saying so. It is now replaced by a model-written summary of itself once the conversation reaches a share of the window, with the recent turns kept verbatim and the swap announced in the transcript.

- On by default at 85% of the window, adjustable in **Settings → Agent**.
- The Chat workspace previously trimmed at a fixed character count regardless of the model, so a 200k-token model forgot turns that were still on screen. It now scales with the window.
- An agent run that would have paused at the context limit compacts and carries on, up to three times per run, and still pauses when compaction cannot help.
- Ask is unchanged: it replays a fixed number of turns and is bounded by construction.

## Standing instructions for Agent, Ask and Chat

**Settings → Instructions** now takes standing preferences that are appended to the model's built-in instructions rather than replacing them.

- Three fields — all AI, Agent only, and Chat and Ask — of up to 4000 characters each.
- Instructions tune how the model works. They cannot grant a permission, approve a command or widen the internet block; those gates are enforced in code the conversation cannot reach.
- Deliberately excluded from tab naming, command suggestions, error explanations and Runbook authoring, each of which has an output contract that free-form text would break.

## Local models on Windows

On-device inference now works on Windows. The installer ships the complete matched llama.cpp runtime and clears stale copies on upgrade and uninstall.

- Setup follows the system language in English or German, and refuses to let an older installer overwrite a newer VTerminal.

## Quieter agent commands over SSH

Agent commands inside an `ssh` or `docker exec` session no longer echo a bookkeeping line before every command.

- The check is taken once per proven shell and reused while nothing about that connection has changed, so three agent steps over ssh read as three lines instead of six.
